Cauli is a network debugging framework featuring a plugin infrastructure to hook into selected request and responses as well as recording and displaying performed requests. It provides a wide range of possibilities. For example from inspecting network traffic to mock UnitTests. Missing something fancy? How about writing your own Plugin.

Features

🌏 Hooks into the URL Loading System
🧩 Existing set of Plugins (Florets)
🔧 Extensible Plugin Infrastructure

Getting Started

Installation

Swift Package Manager

The Swift Package Manager is a tool for automating the distribution of Swift code and is integrated into the swift compiler. Once you have your Swift package set up, add the following to your Package.swift file.

dependencies: [
    .package(url: "https://github.com/cauliframework/cauli.git", from: "1.4")
]

Setup

Add an import Cauliframework to your AppDelegate and call the run function on the shared instance in application(_:didFinishLaunchingWithOptions:). Make sure to call run before instantiating any URLSession. Otherwise Cauli can’t intercept network requests and create any records.

import Cauliframework
import UIKit

@main
class AppDelegate: UIResponder, UIApplicationDelegate {
    func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        Cauli.shared.run()
        // perform your usual application setup
        return true
    }
}

This will configure Cauli to hook into every request, setup the core florets (plugins) (InspectorFloret) and configures a shake gesture for the Cauli UI.

Built-in Florets

  • InspectorFloret lets you browse through and share your requests and responses from within the application. Just shake your device (if you are using the default configuration).
  • MockFloret mocks your network requests, e.g. for tests or to reproduce a bug. It can also record responses for later mocking.
  • NoCacheFloret modifies requests and responses so that no cached data is returned or written to the cache.
  • FindReplaceFloret replaces any part of a request or response, using a RecordModifier.
  • MapRemoteFloret changes the url of a request before it is performed, e.g. to use a staging or testing server.
  • HTTPBodyStreamFloret turns a request’s httpBodyStream into httpBody data, so the body can be inspected and modified.
  • NetworkUsageFloret measures how much the app uses the network, per host and endpoint, and suggests how to use less, based on rules you can extend.
  • NetworkConditionsFloret simulates slow and unreliable networks per host, e.g. 3G, Edge or offline, and remembers every host the app connected to.
  • SecurityAuditFloret finds privacy and security problems in your requests, e.g. credentials over plain HTTP, tokens in URLs or insecure cookies, based on rules you can extend.

Pass the florets you want to use when creating your own Cauli instance:

let cauli = Cauli([InspectorFloret(), NoCacheFloret()])
cauli.run()

For more information read Plugins / Florets.

Writing your own Floret

A floret can process requests and responses, provide its own UI, or both:

  • InterceptingFloret is called before a request is sent (willRequest) and after its response arrived (didRespond). It can modify the Record before passing it on.
  • DisplayingFloret provides a view controller, which is shown in the Cauli UI. It has access to the Cauli instance and thus to its Storage of recorded requests.

This example prints every request and response to the console:

import Cauliframework

final class LoggingFloret: InterceptingFloret {
    var enabled = true
    var description: String? { "Prints every request and response to the console." }

    func willRequest(_ record: Record, modificationCompletionHandler completionHandler: @escaping (Record) -> Void) {
        let request = record.designatedRequest
        print("→ \(request.httpMethod ?? "GET") \(request.url?.absoluteString ?? "-")")
        completionHandler(record)
    }

    func didRespond(_ record: Record, modificationCompletionHandler completionHandler: @escaping (Record) -> Void) {
        let url = record.designatedRequest.url?.absoluteString ?? "-"
        switch record.result {
        case .result(let response)?:
            let statusCode = (response.urlResponse as? HTTPURLResponse).map { String($0.statusCode) } ?? "-"
            print("← \(statusCode) \(url) (\(response.data?.count ?? 0) bytes)")
        case .error(let error)?:
            print("← failed \(url): \(error.localizedDescription)")
        case nil:
            break
        }
        completionHandler(record)
    }
}

willRequest and didRespond are called on a background thread. Always call the completion handler exactly once, with the original or a modified record, otherwise the request won’t continue.

Add it like any other floret, e.g. Cauli([InspectorFloret(), LoggingFloret()]). For more details read Writing Your Own Plugin / Floret.
